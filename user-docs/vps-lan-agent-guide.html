VPS + LAN Agent
Deployment

Run the face_auth backend on any cloud server while controlling Hikvision cameras on a private LAN — no port forwarding, no VPN. The LAN agent creates one outbound connection that carries all traffic in both directions.

30-minute setup Works behind NAT Docker + Go binary

How it works

The key insight: the agent connects out to the VPS, not the other way around. Your LAN doesn't need to accept any inbound connections.

💡
Why this works through NAT: The agent dials out to the VPS over a standard WebSocket (port 443). Your router allows this like any website visit. When the backend needs to talk to a camera, it sends the command through that existing connection — no inbound holes needed.

Prerequisites

  • ✓
    A VPS running Ubuntu 22.04 / Debian 12 (any cloud: DigitalOcean, AWS, Hetzner…)
  • ✓
    Docker + Docker Compose installed on the VPS
  • ✓
    A domain name pointed at the VPS (e.g. face.yourcompany.com) — or just use the VPS IP
  • ✓
    A Windows / Mac / Linux PC on the same LAN as your Hikvision cameras
  • ✓
    Camera's local IP address, ISAPI username and password (default user is usually admin)

Step 1 — Deploy to VPS

1

SSH into your VPS and clone the repo

VPS terminal
git clone https://github.com/yourorg/face_auth.git
cd face_auth
2

Create your environment file

Copy the example and fill in your domain and secure passwords. Never commit this file.

VPS terminal
cp .env.vps.example .env
nano .env
.env — minimum required values
PG_PASSWORD=change-me-strong-password
MINIO_ROOT_PASSWORD=change-me-strong-password

# Your domain or VPS IP
VITE_API_URL=https://face.yourcompany.com
3

Start the stack

VPS terminal
docker compose -f docker-compose.yml -f docker-compose.vps.yml up -d --build
docker compose ps   # all services should show "healthy"
🔐
If you have a reverse proxy (Nginx / Caddy), point it at localhost:8084 (API) and localhost:8085 (admin UI). The docker-compose.vps.yml binds only to 127.0.0.1 so ports are not exposed publicly.
4

Open the admin UI and log in

Visit https://face.yourcompany.com (or your VPS IP on port 5173 during testing).

Step 2 — Install LAN Agent

This runs on any PC that can reach your cameras. It does not need to be a server — a spare office PC works fine.

1

Download the agent binary

In the admin UI: go to Agents → Add agent → give it a name (e.g. Office LAN) → Save. The page shows the Agent ID and Token — copy the token now, it won't be shown again.

face.yourcompany.com → Agents

ID: office-lan · connected just now

Branch KL
ID: branch-kl · never connected
Offline
2

Run the agent on the LAN PC

Download the correct binary for your OS, then run it with three environment variables: the VPS URL, your agent ID, and the token.

macOS / Linux

LAN PC — Terminal
chmod +x face_auth-agent

CLOUD_URL=wss://face.yourcompany.com \
AGENT_ID=office-lan \
AGENT_TOKEN=your-token-here \
./face_auth-agent

Windows (PowerShell)

LAN PC — PowerShell
$env:CLOUD_URL   = "wss://face.yourcompany.com"
$env:AGENT_ID    = "office-lan"
$env:AGENT_TOKEN = "your-token-here"
.\face_auth-agent.exe
✓
When the agent connects successfully, a dashboard opens at http://127.0.0.1:7780 showing its status. The admin UI Agents tab also shows it as Connected.
3

Run as a background service (recommended)

Pass --service to skip the browser dashboard and run silently. Use your OS service manager to keep it running on startup.

macOS — run in background
CLOUD_URL=wss://face.yourcompany.com \
AGENT_ID=office-lan \
AGENT_TOKEN=your-token-here \
./face_auth-agent --service > agent.log 2>&1 &

Or use the provided start.sh script in the project root — it handles building and starting the agent automatically alongside the Docker stack.

Step 4 — Add a camera via agent

1

Go to Devices → Add device

Fill in the device's local IP (e.g. 192.168.1.64), port (usually 80), ISAPI username, and password.

2

Set "Reach via" → Via agent

Pick the agent you just connected from the dropdown. The device IP is the camera's address on the LAN — not visible from the VPS, but reachable from the LAN PC running the agent.

Step 5 — Verify it works end-to-end

Enrol a test person and confirm the camera receives their data.

1

Create a person and add a card

Go to Persons → Add person. Fill in a name and employee ID. Add a card number under the Cards section.

2

Push to device

Open the person, scroll to the device section, pick your device, and click Push to device. Within a few seconds you'll see a success response.

✓
Success means: VPS → WebSocket → Agent → Camera ISAPI → back. The full chain is alive.
3

Test at the door

Present the card (or face) to the camera. The door should unlock and the event appears in the Events tab of the admin UI.

Ports & firewall

Only the VPS needs open ports. The LAN PC only makes outbound connections.

PortHostOpen toPurpose
443 VPS Internet HTTPS + WebSocket (wss://) — reverse proxy terminates TLS here
80 VPS Internet HTTP → redirect to HTTPS only
8084 VPS localhost Backend API (behind reverse proxy)
8085 VPS localhost Admin UI (behind reverse proxy)
7780 LAN PC localhost Agent dashboard (local only)
80 Camera LAN only ISAPI — only the agent needs to reach this
🔒
The LAN PC does not need any inbound ports open. It only makes outbound connections to the VPS (port 443) and to cameras (port 80) on the same LAN.
